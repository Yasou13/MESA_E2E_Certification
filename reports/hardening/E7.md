# E7 — Raw/Scored Separation and Oracle Barrier

PHASE: E7

STATUS: GREEN

BASE SHA: `8a09cc5`

PHASE COMMIT: commit containing this report (`e2e-07`)

PROBLEM REPRODUCED: CONFIRMED. The historical run uses flat aggregate raw and
score artifacts, lacks exact request/transport/latency/runtime envelopes, and
does not retain exact model-visible answer context/prompts. Oracle/context
consistency therefore cannot be independently established.

ROOT CAUSE: Raw capture, immutable sealing, scored-lane ordering, and recursive
oracle inspection were documentation requirements without a common executable
storage boundary.

FILES CHANGED: Raw/scored artifact store, oracle auditor, E7 tests, harness
documentation, four deferred MESA contract notes, and this report.

TESTS ADDED/CHANGED: Four-lane layout, canonical request/response hashes,
bounded raw response, raw seal, score-before-raw rejection, post-seal mutation,
unowned historical-directory protection, opaque exact-context capture, nested
oracle fields/prompt tokens, redacted audit output, and failed-audit scoring
barrier.

OLD BEHAVIOR: Score output could be produced without a byte-exact raw record or
oracle audit; requests and answer context lacked auditable envelopes.

NEW BEHAVIOR: Retrieval raw envelopes contain exact request/response, transport
status, UTC timestamp, latency, runtime-lock hash, and canonical hashes. Answer
captures preserve opaque exact context, evidence IDs/hash, exact prompts,
provider/model/parameters, raw response, and parsed response. Every artifact is
sealed; scoring requires intact raw bytes and a sealed PASS oracle audit.

FALSE-PASS CANARIES: Required facts, qrels, gold evidence IDs, expected labels,
or expected answers in nested requests/prompts/context; score before raw;
mutated raw seal; failed/missing oracle audit; initialization over an unowned
non-empty run directory.

FALSE-FAIL CANARIES: Clean execution surfaces pass oracle audit; canonical raw
capture persists and can be scored after its seal and audit pass; opaque context
round-trips byte-equivalent canonical JSON.

FREEZE / ORACLE IMPACT: Oracle findings redact values and are themselves sealed.
Raw artifact hashes bind every scored record. The exact MESA context adapter is
not fabricated and remains WAIT_FOR_MESA_PHASE_10.

BACKWARD COMPATIBILITY: Historical flat run evidence remains readable and
untouched but cannot be silently adopted as a new mutable E7 run layout.

MESA CONTRACT DEPENDENCY: WAIT_FOR_MESA_PHASE_1, WAIT_FOR_MESA_PHASE_7,
WAIT_FOR_MESA_PHASE_8_9, and WAIT_FOR_MESA_PHASE_10. Requirements, versioning,
fail-closed semantics, and future tests are recorded under `contracts/`.

METHODOLOGY DECISION REQUIRED: NONE

FOCUSED TEST RESULT: 7/7 E7 storage/oracle tests passed.

RELEVANT SUITE RESULT: 58/58 pytest tests and optimized 17/17 self-tests passed.

KNOWN LIMITATIONS: No final product adapter is bound. The generic capture stores
the exact opaque value supplied by the future adapter; proving that it is the
actual post-formatting model context waits for MESA Phase 10.

WHY SAFE TO CONTINUE: This phase adds only fail-closed evidence plumbing and
explicit deferred interfaces; it neither injects GT into execution nor guesses
future MESA response/context schemas.
