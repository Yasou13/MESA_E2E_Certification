# E8 — Health, Resource, Finalization, and Release Bundle

PHASE: E8

STATUS: GREEN

BASE SHA: `5e5dc0b`

PHASE COMMIT: commit containing this report (`e2e-08`)

PROBLEM REPRODUCED: CONFIRMED. The repository specified pre/post health,
resource telemetry, a runtime lock, and a sanitized release bundle, but lacked
executable typed writers, fail-closed operational evaluation, and an atomic
release promoter.

ROOT CAUSE: Mandatory operational evidence and promotion rules existed only as
documentation; no common code enforced their schema, completeness, RUN_ID
coherence, secret boundary, or checksum coverage.

FILES CHANGED: Operational evidence models/writers, release finalizer/verifier,
E8 tests, harness/release documentation, and this report.

TESTS ADDED/CHANGED: Healthy and unverified health snapshots; restart/OOM and
missing resource telemetry; secret-free runtime lock plus hash sidecar; missing
release artifact; forbidden release field; complete release promotion; checksum
verification; and post-promotion mutation detection.

OLD BEHAVIOR: A run could not generate the required health/resource/runtime
artifacts through a typed API, and an incomplete or unsafe summary collection
had no executable barrier to tracked release promotion.

NEW BEHAVIOR: Health and resource evidence has strict versioned schemas and
explicit PASS/FAIL/UNVERIFIED results. Runtime locks reject credential fields.
The finalizer requires the exact sanitized artifact set, validates schema and
RUN_ID coherence, rejects oracle/secret-bearing fields and token signatures,
writes deterministic checksums, and atomically promotes only a verified bundle.

FALSE-PASS CANARIES: Missing post-test health, secret-bearing decision summary,
OOM/restart/critical pressure, provider request usage above twice expectation,
non-PASS mandatory operational summaries under a PASS verdict, incomplete
checksum coverage, and mutated promoted content.

FALSE-FAIL CANARIES: A complete coherent sanitized fixture promotes, verifies,
and remains readable; normal operational observations return PASS; unavailable
telemetry is distinguished as UNVERIFIED rather than fabricated FAIL or PASS.

FREEZE / ORACLE IMPACT: Runtime and configuration identities are hash-bound in
the runtime lock. Release promotion rejects raw responses, prompts, exact model
context, qrels, required facts, and gold evidence IDs so the compact tracked
bundle does not become an oracle channel.

BACKWARD COMPATIBILITY: No historical evidence or existing release directory is
modified. Existing destinations are immutable from the finalizer's perspective
and cause a fail-closed error.

MESA CONTRACT DEPENDENCY: NONE for the framework. Actual product health probes
and runtime population remain future integration inputs and are not fabricated.

METHODOLOGY DECISION REQUIRED: NONE for E8 implementation.

FOCUSED TEST RESULT: 5/5 E8 operational/finalizer tests passed.

RELEVANT SUITE RESULT: 63/63 pytest tests, optimized 17/17 self-tests, compile,
agent-pack integrity, no-secret scan, and JSON/JSONL validation passed.

KNOWN LIMITATIONS: This hardening loop is not a live certification run and
therefore produces no release bundle with claimed product health. Provider token
counters and product-specific probes must be supplied by the eventual adapter.

WHY SAFE TO CONTINUE: The phase adds only generic, fail-closed evidence and
promotion mechanisms; it neither asserts unavailable runtime facts nor alters
benchmark data, thresholds, historical evidence, or external repositories.
