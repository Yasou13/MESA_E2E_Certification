# E2 — Identity, Normalization, and Core Schemas

PHASE: E2

STATUS: GREEN

BASE SHA: `6a18332`

PHASE COMMIT: commit containing this report (`e2e-02`)

PROBLEM REPRODUCED: CONFIRMED. `IdentityMap` silently overwrote conflicting
MESA IDs, returned unknown IDs unchanged, hashed decoded text rather than the
source bytes, and normalization behavior was duplicated in Python instead of
loaded from the frozen config. Required versioned core models were absent.

ROOT CAUSE: Mapping and normalization code was permissive and lacked a strict,
versioned input/output boundary.

FILES CHANGED: Identity loader/resolver, normalization authority and config,
core models, both scorers' mapping-error handling, self-test canaries, and E2
tests.

TESTS ADDED/CHANGED: Conflict, duplicate, malformed row, unknown ID, binary
hash freeze, deterministic validation artifact, config-authority, normalization
hash, strict/versioned models, and scorer mapping-integrity tests.

OLD BEHAVIOR: Unknown IDs could be ordinary misses, conflicts could overwrite,
and changing normalization config did not change executable semantics.

NEW BEHAVIOR: Mapping integrity fails closed as `MAPPING_INTEGRITY_ERROR`;
JSONL/schema and frozen SHA are verified before state mutation; normalization
is loaded from one hashed authority; serialized match IDs are stable-sorted.

FALSE-PASS CANARIES: Unknown and malformed evidence cannot become MISS/HIT;
conflicts and duplicates cannot load; SHA drift prevents map/config use.

FALSE-FAIL CANARIES: Known authoritative source IDs resolve directly; all
5,721 mappings in the preserved historical identity map validate without
rewriting that artifact; documented Turkish law/article fixtures remain green.

FREEZE / ORACLE IMPACT: Identity and normalization now expose byte-exact hashes
for E4 freeze use. No oracle-bearing or historical run artifact was changed.

BACKWARD COMPATIBILITY: Valid historical identity rows and existing scorer
interfaces remain accepted. Unknown-ID fallback and malformed-result-as-MISS
were intentionally removed as unsafe behavior.

MESA CONTRACT DEPENDENCY: WAIT_FOR_MESA_PHASE_1 for the final evidence-level
retrieval adapter. Broad provenance scoring is deliberately not finalized here.

METHODOLOGY DECISION REQUIRED: NONE

FOCUSED TEST RESULT: 8/8 E2 tests passed.

RELEVANT SUITE RESULT: 16/16 pytest tests and optimized 17/17 self-tests passed;
the historical identity map loaded as 5,721 strict mappings.

KNOWN LIMITATIONS: Final first-class retrieval evidence semantics remain
deferred to WAIT_FOR_MESA_PHASE_1; answer grading semantics belong to E3.

WHY SAFE TO CONTINUE: The phase only tightens malformed/unknown identity and
normalization boundaries, preserves valid inputs, and introduces no threshold,
holdout, or verdict methodology change.
