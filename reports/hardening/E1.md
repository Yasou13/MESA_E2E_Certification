PROBLEM REPRODUCED: CONFIRMED. The host Python could not import the undeclared
`pydantic` dependency, no project/lock/CI/test contract existed, and the
self-test used removable Python `assert` statements throughout.

ROOT CAUSE: The executable harness had no packaging or CI authority, while its
custom test runner relied on interpreter optimization-sensitive assertions.

FILES CHANGED: `pyproject.toml`, `uv.lock`, CI workflow, foundation scripts,
foundation tests, harness self-test, and harness/scripts documentation.

TESTS ADDED/CHANGED: Compile/import checks, frozen agent-pack checksum and
membership validation, high-confidence no-secret scan, tracked JSON/JSONL
syntax validation, self-test report validation, and optimized-Python execution.

OLD BEHAVIOR: Dependency availability was ambient, CI was absent, and
`python -O` removed the self-test's correctness checks.

NEW BEHAVIOR: `uv.lock` controls exact dependencies, CI executes the locked
environment, and production self-test invariants raise explicit exceptions.

FALSE-PASS CANARIES: AST check forbids `assert` in the production self-test;
the self-test is run under `python -O`; checksum, secret, and artifact checks
return non-zero on failure.

FALSE-FAIL CANARIES: Agent-pack membership intentionally excludes `.gitkeep`;
secret scanning uses only high-confidence credential formats and skips binary
and oversized evidence files.

FREEZE / ORACLE IMPACT: No run evidence or oracle-bearing data was modified.
The foundation provides deterministic inputs for later freeze/oracle phases.

BACKWARD COMPATIBILITY: Existing 17 self-test cases retain their E1 semantics.

self-test, and pytest checks passed.
